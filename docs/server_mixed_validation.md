## R4：锁与停止确认

本批在进入混合回归时补齐 R4 两个确定缺口。原 `finally` 已有 active 身份检查，不能把问题误写成原实现无条件清空 active；缺口是停止确认没有独立释放路径，以及锁接口是可选调用。

- 写锁缺少任一 acquire／release 接口时，容器任务现在明确返回 UNSUPPORTED。真实 MCP → ServerBody → 本地 HTTP 夹具确认过旧版本未拒绝，以及旧 observe 响应延迟时停止已确认、首新任务仍被 BUSY 拒绝，两个红例均已修正。
- cancel 立即废弃旧步骤与引用，但保留锁；只有最新匹配的停止句柄收到 `stopped:true` 才释放。停止失败／未确认时仍保留 BUSY，旧停止回执或旧 finally 不得清理新任务的锁。
- 确认停止后不等待旧 HTTP 过程返回即可接新任务。迟到的可靠部分丢物回执继续保留计数，整体为 cancelled；迟到 unknown 保持 unknown，不因取消而冒充已知无副作用，也不触发自动清理或补做。
- 新增七项确定性用例。容器定向 43/43、完整运行端 **157/157** 通过；真实混合矩阵另行记录，不以离线结果代替。
