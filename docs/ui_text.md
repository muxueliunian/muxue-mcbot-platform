# 界面文案规范

2026-10-10 用户定：界面上给人看的文字一律用书面语，禁止口语化描述。例如插件状态写「已安装」「未安装」，不写「已装好」「没装」。

## 适用范围

| 适用 | 不适用 |
| --- | --- |
| WebUI 页面上的文字：标签、按钮、状态、提示、确认框、悬停提示、占位文字 | 代码注释、开发文档（`docs/`） |
| WebUI 接口返回、会显示在页面上的提示和错误（`scripts/webui*.mjs`、`agent-models.mjs`） | 给 AI 的工具说明、提示词 |
| 托管启动脚本的提示和错误（会写进页面上的等待状态和启动日志，`start-server-play.mjs`） | Bot 在游戏里的聊天、人设和人设示例（说话风格本来就要口语） |
| 绿色版的 `使用说明.txt`（`package.mjs`）、打包脚本的报错 | 游戏里的日志和协议错误码 |
| `compat.json` 里展示给人的字段（`name`、`what`、`evidence`、`where`、`login`），网站和 WebUI 插件页都读它 | |

## 规则

1. **用书面语。** 不用语气词（啦、呀、吧、哦、呢、嘛、嗯），不用口语动词和程度词（弄、搞、挺、蛮、东西、一下）。
2. **状态用固定词。** 同一种状态在所有地方用同一个词，见下面的状态词表。
3. **不称呼「你」。** 要求对方做事用「请……」，或者直接写动作。
4. **句式：**
   - 标签、标题：名词短语（「游戏目录」「保护范围（格）」）。
   - 按钮：动词或动宾短语（「安装」「保存并启动托管」「删除此配置」）。
   - 提示：完整的陈述句；多个分句之间用「；」，结尾可以不加句号。
   - 错误：先写原因，再写处理办法，例如「未选择游戏。请先在「连接配置」中选择游戏」。
   - 确认框：用问句写清后果，例如「停止托管 Claude？Bot 将下线」。
5. **指代用「此」「该」「当前」**，不用「这个」「那个」「现在的」。
6. **保留专有名词和代码原文**，比如 mod id、文件名、命令、`machine-items`。界面上的名称用「」括起来，比如「连接配置」「对局域网开放」。

## 状态词表

| 场合 | 用 | 不用 |
| --- | --- | --- |
| 插件、模组 | 已安装、未安装、需更新、需修复、旧版本、版本不匹配 | 已装好、没装、要更新、要修、旧版、版本不对 |
| 世界、服务器 | 运行中、未运行、尚未打开过世界、尚未启动过 | 开着、没开、还没开过 |
| 托管 | 在线、思考中、等待中、启动中、已停止、已结束、启动失败、异常退出 | 没起来、跑了一阵后退出了、游戏关了 |
| 读写 | 读取中、无法读取、未找到、无法连接、格式错误、已保存 | 读不了、读不到、找不到、连不上、格式不对 |
| 校验 | 须为……、仅可……、不支持的…… | 要是……、只能……、不认识的…… |
| 进度 | 尚未……、已完成、执行中 | 还没……、好了、正在做 |

常用替换：要（必须）→ 须／需；能 → 可；不能 → 无法／不可；就 → 则（或删去）；里 → 中；名字 → 名称；不用 → 无需；点 → 点击；放进 → 复制到／安装到；改完 → 修改后；别 → 请勿；以后支持 → 暂不支持。

## 检查

```pwsh
node scripts/check-ui-text.mjs          # 查禁用词，有就列出位置并以 1 退出
node scripts/check-ui-text.mjs --list   # 列出取到的全部中文文案，人工通读用
```

脚本从上面适用范围里的文件取出字符串字面量和页面文字（跳过注释、正则和人设示例），按禁用词表检查；`mcp-server` 的 `npm test` 也会跑。禁用词表只收口语里才会出现、不容易误伤的写法。句式和用词统一靠 `--list` 人工通读，新增或修改界面文字后都要读一遍。
