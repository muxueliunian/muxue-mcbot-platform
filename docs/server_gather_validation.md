# ServerBody 数量与有限采集首批（2026-10-03）

> 这是原开发环境的历史验证记录。原始日志、账号环境与测试存档未随整理版上传；整理版自己的复验见 [export_validation.md](export_validation.md)。
本批在持续陪伴基础上增加有限采集，不开启另一套Minecraft客户端。Agent选择目标和数量，共享任务层执行选工具、走近、挖掘和拾取；实际获得量来自原生拾取事件，而不是破坏方块数或背包净变化。

## 接口与数量

完整能力集新增3个MCP工具，共33个：

- `discover-resources`：指定1–8个受支持的方块ID，扫描半径1–6、最多64个已加载可见候选；返回一个绑定当前候选集合的`resourceRef`，30秒内提交。不会区分天然树与人工建筑，Agent必须依据用户授权选范围。
- `gather-resources`：针对一次发现的固定候选，先拾取范围内匹配掉落，再逐个选工具／走近／挖掘／拾取；不为凑数自动扩区或重新扫描。异步返回，可同时聊天。
- `collect-items`：只捡初始观察范围内的指定掉落实体，不挖块，也不追加后来出现的其他UUID。

资源方块ID与目标物品ID分开：采圆石应发现`minecraft:stone`并以`minecraft:cobblestone`为获得目标；圆石方块本身不在本批资源目录。最终Claude首轮曾把两种ID都用于发现，被明确拒绝后改为石头成功；工具指引仍有减少这种额外往返的空间。

有限任务必须给`count`或`stacks`之一。玩家没说数量时，由Agent根据用途、附近资源和空间决定明确目标，并在开工的`say`里说明；程序不默认64或无限任务。1组按实际目标栈`maxStackSize`换算；这个字段来自游戏端实际`ItemStack.getMaxStackSize()`，考虑组件与Mod效果，不等于机器槽容量或当前不足额栈数量。

实际样栈只能来自授权来源。新采集不会用旧背包里同ID、不同组件的物品推断目标变体；没有样栈时，可在授权候选内从第一份真实拾取确认上限和变体。数量一经确定不随上限变化悄悄重算；不同组件不会混计。解析后目标本批最多256个，超过则明确拒绝，不静默截断；执行步骤和时间另有预算，默认64个原子步骤／60秒，上限256步／120秒。预算不足或资源不够必须报告部分结果。

容器／交物任务同样支持`count|stacks`，仍限单个足量源栈；取物需要空快捷栏，不跨源栈转移。大于64的单栈交物按不超过64的原子动作分批，逐批重新核验完整组件、数量和有效上限。它们的“丢出”仍不等于指定玩家已拾取；不混同本批Bot自己的原生拾取归因。

## 原生动作与边界

Java新增`nearby-resources`、`approach-resource`和`pickup-item`。首批资源catalog为5种石料（stone、deepslate、granite、diorite、andesite）和8种1.21.1主世界原木；只处理角色当前脚面及以上的有限目标。禁止挖玩家支撑、与玩家身体相交的块、方块实体，以及邻接危险／流体／上方重力方块的目标。不挖地板矿洞，不砍完整高树，不搭桥或挖路；矿石／Mod方块需要后续明确适配。

资源引用绑定会话、控制代次、维度、位置、完整BlockState与加载区块实例，游戏端固定120秒有效、最多256条；不是普通方块的独立实例身份，因此不声称能辨别同区块内完全同状态的替换。

地面观察含UUID、位置、完整物品栈、实际`onGround`和可见性，半径8、最多32个，并标注截断。原生NeoForge拾取Post事件产生带游标的收据，记录实际角色、实体、完整栈片段与数量；记录上限256，缺口必须停止。物品消失、其他玩家抢捡、单纯背包增加都不能冒充目标拾取。

`minedBlocks`和`pickedUpCount`分别报告已确认挖块与新拾取；原生整栈拾取可能超过目标，`overage`如实保留。意外获得物品另列；未知或取消保留`lastConfirmedPickedUpCount`，不伪称当前总量完整。控制／世界／变体／上限变化及未知结果不盲重试。停止复用独立控制链，旧任务不会恢复，已发生的世界变动不自动回滚。

## 本轮定位并修复的缺陷

1. 新增有效堆叠上限后，旧取物回执比较必须保留该字段；同时不能把旧背包变体当成新采集来源。
2. 物品在原生自然触碰时已被收取，实体随后消失：只有对应UUID的真实新收据才能判定已领取，不能误报丢失或盲目再捡。
3. 已确认挖掘成功后，下一次观察可能失败；现先保存挖除计数，避免实际挖了却报告0。
4. 刚生成的掉落在同一tick或抛物线顶点可能短暂位置相同。现在等待真实落地且持续稳定≥200毫秒；旧服务端无落地字段时用≥400毫秒保守稳定期，总等待≤2.5秒并受任务总时限约束。原子目标移动保护未放宽。
5. 拾取和资源交互的规划终点可能恰在可达边界，移动容差却让角色提前停在范围外。规划增加0.2格水平裕量，实际原版范围／视线不变；共享走近的资源、容器和玩家分支均覆盖。过窄而无足够裕量站位的环境仍会拒绝。
6. 在已完整核验当前上下文、变体和同一UUID的本次新拾取收据后，数量目标已达到，可完成任务并保留已知辅助移动失败的诊断。目标未满的危险／受伤BLOCKED、未知、收据缺口、其他UUID、变体或会话变化不会被吞掉。
