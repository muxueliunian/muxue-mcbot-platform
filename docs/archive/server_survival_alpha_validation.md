# 生存 Alpha 第一批：物品、工具与进食

2026-10-03。在独立整理仓库继续开发，基线为 `e76df37`。**第一批核心功能已实现并实测；尚不是完整生存 Alpha。** 高差导航、自卫、战斗威胁感知及建筑执行仍未交付，高差导航原型本批也未运行。

## 交付能力

| 入口／行为 | 本批实际范围 |
| --- | --- |
| `prepare-item` | 主背包0–35槽的物品准备到热栏0–8，执行原生整栈SWAP与选槽；默认空槽，显式targetSlot允许交换占用槽。不丢弃、不恢复旧库存快照；拆分、任意两主背包槽整理、护甲／副手和背包Mod另验 |
| `assess-tool` | 全主背包候选，区分基础掉落资格、基础速度估计、耐久、精准采集／时运与未知；默认fastest_valid，同速优先当前槽，默认保留最后2耐久。允许conserve_durability及明确掉落偏好；不是完整Mod钩子后的实际耗时预测 |
| 采集工具准备 | 原有限资源任务已接评估与背包准备；采圆石排除精准采集冲突，原生开挖再走当前位置的HarvestCheck。资源仍限既有石料／原木目录；能评估铁矿／黑曜石不等于已开放这些采集任务 |
| `eat-food` | 明确吃一份安全食品，可从主背包准备；热栏全满时守卫交换当前槽。用原生使用时长和本次主手Finish事件确认消费，随后核对实际结果；不能用饥饿／库存净变化代替因果收据 |
| 默认自动进食 | 无需模型逐口调用；闲时进食，采集每格间隙可借外层token进食，紧急时先停旧任务再取得唯一写权。紧急抢占不自动重放旧任务。普通成功进食不逐次唤醒模型，缺食物／未知／重要抢占才通知 |
| `get-survival-state`、`set-reflexes` | 读取原生状态、食物候选、有效策略与revision；修改开关、阈值、保护食品、工具策略。策略改变先停止活动任务，避免旧策略继续写；hard stop解除armed，读状态／聊天不重启它，新明确任务或armed:true才能重新授权 |
| 组件观察退化 | 自身库存中不可完整编码的物品保留ID/count及componentsComplete:false，省略components并标不可操作；不得伪造空对象。容器／地面物品整体退化尚未完成，不宣称R6全部关闭 |

现在完整ServerBody有**38个MCP工具**。新增五个语义入口，Claude及Codex工具允许列表均已接入；本批新增能力只做了实际Claude测试，Codex实际新增工具回归仍待做。

首版食品只接受已核验的普通原版语义；有负面／特殊效果、特殊消费实现或未知Mod食品拒绝自动消费。金苹果等保护／特殊食品不算本次可用范围，程序也默认保护金胡萝卜。不能外推为任意食品组件安全。

## 仲裁与本批修复

仍由Node单一仲裁入口管理写权，服务器负责权威事实和原生动作；没有另外一条偷偷改变控制代次的自动执行通道。RuntimeMonitor在陪伴切换早退前读取紧凑生存信息，不等待整顿饭才处理后续观察；使用tick仍在游戏端。

本批补了以下可确定复现的边界：

- 借锁进食结果unknown时，父采集必须等停写确认才释放锁；停止失败时父／子屏障均保留。
- 已确认停止不等于允许自动重试未知的那顿饭。借锁或手动步骤unknown会停用本能，不能被下一次饥饿观察隐式重试。
- 自动进食不抢占正在正常执行的手动进食。策略修改使旧任务失效并等待停止确认；迟到结果不能重新启动动作。
- 紧急缺食物通知按紧急状态转换去重，避免普通缺食物→紧急缺食物时第一条危险通知也被吞。
- 工具评估与准备之间若栈改变，按完整候选快照拒绝，而非把同槽的新物品当成已评估工具。
- 第一次实服暴露`assess-tool`缺少dimension，运行端拒绝回执且未进行后续动作；已修服务端字段，并用完整实服矩阵复验。

## 真实隔离服程序矩阵

MC1.21.1／NeoForge21.1.217，单ServerBot，本机Agent运行端；新仓库`runtime/serverbody-validation`副本，端口25568／25578／8766。普通模式，没有测试夹具开关；RCON只布置夹具和独立读取，产品写入经真实stdio MCP／原生动作完成。

完整扩展矩阵：**47项通过，22.560秒**。测试MCP与协议玩家均正常exit0。包含：

- 木／石／铁／金／钻镐的石头资格与基础速度；木镐／金镐不能获得铁矿掉落，铁镐不合格黑曜石、背包中的钻石镐合格。
- 砍木／沙子分别推荐斧／铲；近坏金镐保留最后耐久，显式改变策略后才允许选择。
- 每次只读评估前后核对完整库存及选槽，并用RCON库存独立对照，确认评估没有临时换手。
- 主背包10→占用热栏0的原生交换，全背包字段对拍守恒；满热栏且未指定目标时拒绝。
- **镐只在主背包时实际采石成功**：链路包含swap-inventory及dig-block，原生拾取收据确认1圆石；服务端独立确认石头移除及圆石库存。
- 原生进食只消费1面包；途中stop后不延迟消费、不重新发eat-item；停止后首个准备任务成功。
- 自动进食开启后消费、关闭后不再消费；无食物先进入wait，再引入食物触发紧急抢占，确认原生消费、wait不恢复及新任务可用。

先前37项矩阵也通过，不能与扩展47项相加。第一次扩展尝试的测试宿主发生原生退出，因此该次**未完成，不计通过**；修复漏维度后的功能结果与这次环境异常分别记录。

## 实际 Claude-b

使用当天用户指定的本机Claude-b，Sonnet5.5／low，单个受限CLI会话，实际初始化可用工具为38个Minecraft MCP工具；沿用生产权限构造，不恢复宿主Read／Write／Bash。先无食物启动，由模型关闭自动进食后再引入面包，避免把程序自动消费误算成模型手动任务。

**五个固定评测输入全部通过**，不是玩家聊天或托管唤醒时延验收：

| 阶段 | 首工具调用 | 阶段完成 | 实际核对 |

## Node原生退出：保留限制

全局Node24.15.0（V8 13.6.233.17-node.48／libuv1.51.0）、Windows11 build26200上，扩展脚本主进程以**-1073740791／0xC0000409**退出，没有JS堆栈，finally未执行。已记录原进程、最后检查点，给自身协议玩家发送quit，确认自身MCP／peer退出并清理本轮forcechunk；没有清理其他会话。

本机已有的独立Node24.19.0（V8 node.51／libuv1.52.1）上，相同完整47项矩阵、实际Claude五阶段以及206项运行端回归通过。**这是经过测试的运行时选择，不是全局升级，也不是对原崩溃的根因证明。** 原Node24.15的独立tasks测试循环20次均通过，未形成稳定最小复现；CrashDumps／WER没有找到该Node的原生栈。

上游有[Windows Maglev相近症状](https://github.com/nodejs/node/issues/62260)和[libuv TCP keepalive初始化修复](https://github.com/nodejs/node/pull/62561)，只能作为后续诊断线索，不能直接把本机问题或更早的历史退出归因给它们。

补充的纯node:net本机keepalive循环3轮亦未复现：共7200对连接／14400次keepalive，0次失败，不加载MCBOT或第三方包。因旧版本没有稳定红例，没有把新旧版本的绿绿对照冒称根因验证；所有诊断脚本留在本地output。

`start-server-play.ps1`现支持可选`-NodePath '<本机Node可执行文件>'`，同时供宿主与MCP使用，默认仍遵从PATH。建议本机后续先明确选择本次通过的24.19运行时；未修改全局Node、注册表或其他Agent配置。
