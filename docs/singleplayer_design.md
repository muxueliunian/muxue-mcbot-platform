# 设计：单人模式（内置服务器）

2026-10-06 草案，对应 [交付计划](delivery_plan.md) 第 2 步。单人模式指：玩家在自己的客户端里装上 `mcbot-server-control`，开单人世界，Bot 由内置服务器（IntegratedServer）承载，不需要另开服务器。观众大多玩单人，所以这是试玩门槛最低的形态。

## 1. 现状和查到的事实

模组的依赖声明是两端都可装，`ServerStartedEvent` 在单人世界打开时也会触发，控制桥照常启动。没有实际在单人世界里跑过。以下按 MC 1.21.1 / NeoForge 21.1.217 源码核对：

| 事实 | 出处 | 影响 |
| --- | --- | --- |
| 打开暂停界面（ESC，或者窗口失焦且开着「失焦暂停」，这是默认设置）且没有开局域网时，内置服务器暂停 | `Minecraft` 第 1235 行、`IntegratedServer.tickServer` | 暂停期间不跑世界 tick，`ServerTickEvent` 不触发 |
| 暂停时服务器线程的任务队列照常处理 | `MinecraftServer.waitUntilNextTick` | HTTP 调用照常应答：观察、聊天记录、心跳都能用，租约不会过期 |
| 暂停的瞬间会自动存档一次 | `IntegratedServer.tickServer` | 无影响 |
| 服务端可以直接读暂停状态：`server.isPaused()` | `IntegratedServer.isPaused` | 不用引入客户端类 |
| 开局域网后不再暂停 | 同上 | 行为和独立服务器一样 |
| 局域网勾了「允许作弊」后，所有玩家都算 OP | `PlayerList.isOp` | 身体会以「拒绝 OP 身份」拒绝接管 |
| 配置在实例的 `config/mcbot-server-control/`，所有存档共用 | `FMLPaths.CONFIGDIR` | 每个世界的 `worldId` 都一样，记忆会串 |
| 每次打开世界都会重新生成 `connection.json` 的令牌；退出到标题时控制桥关闭 | `LocalHttpBridge`、`ServerStoppingEvent` | 运行端失去控制后是终止态，要手动重启托管 |

## 2. 要解决的问题

1. **暂停**：动作在暂停时冻结，但超时和「无进展」用的是真实时间。玩家按 ESC 超过 2～3 秒再回来，跟随会以「无进展」失败，采集等有限任务会超时，陪伴模式进入受阻。这是最常见的情况（切窗口去看终端也会暂停）。
2. **记忆串世界**：所有单人存档共用一个 `worldId`。
3. **退出再进**：退出到标题后，托管进程要手动重启，令牌也变了。
4. **局域网加作弊**：Bot 被当成 OP，拒绝接管，提示也不够清楚。

## 3. 方案

### 3.1 暂停：中止当前动作，陪伴自动恢复（推荐）

ServerBody：

- `observe`、`survival-state`、心跳回执都带上 `paused: true/false`（来自 `server.isPaused()`，独立服务器永远是 false）。
- 检测到暂停时，正在执行的动作以 `failed`、代码 `GAME_PAUSED` 结束。已经发出原生效果但还没确认的，照现有的 `NativeActionBoundary` 规则报 `unknown`，不重试。
- 暂停期间新的 `act` 在写入前就以 `GAME_PAUSED` 拒绝。读操作照常。
- 不推进控制代次，不撤销租约：暂停不是失去控制。

运行端：

- 陪伴模式：子动作或跟随因 `GAME_PAUSED` 结束时，进入「暂停」状态（原因 `game-paused`），保留玩家、距离、拾取和陪挖的配置和预算；观察到 `paused` 变回 false，自动恢复跟随。用户手动说的暂停不会被自动恢复。陪挖的总时长在暂停期间照常流逝（和现在手动暂停一致）。
- 有限任务（采集、拾取、开箱、交互）：以 `GAME_PAUSED` 失败，事件里告诉模型「游戏暂停了，任务已中止，恢复后可以重新下达」，不自动重试。
- 自动进食、自卫在暂停时不触发。
- 暂停和恢复本身不唤醒模型，省 token；只有任务被中止时才发一次事件。

**另一种做法：冻结**。暂停期间所有超时都不计时，恢复后动作接着做。体验更好，但要把服务端多处计时（导航、拾取、跟随、接近、退让、进食等）和运行端任务层的截止时间全部改成「扣掉暂停时长」，改动面大，容易漏。建议先做「中止＋陪伴自动恢复」，试玩后如果觉得有限任务被 ESC 打断太烦，再升级成冻结。

玩家侧的建议写进试玩文档：按 F3+P 关掉「失焦暂停」，切窗口时就不会暂停；或者开局域网（不勾作弊）。

### 3.2 每个存档自己的 worldId

`server.json` 的 `worldId` 支持 `"auto"`：使用 `sp-<存档文件夹名>`（只保留字母数字、`-`、`_`，最长 48 个字符）。内置服务器上第一次生成配置时默认写 `"auto"`；独立服务器默认值和已有配置都不变。

### 3.3 退出再进

第一版保持现状：退出到标题后托管进程结束，提示「重新进世界后再运行一次启动脚本」。启动脚本加一个 `-Instance <实例目录>` 参数，自动去 `<实例>/config/mcbot-server-control/connection.json` 找连接文件，找不到就提示先进世界。自动重连（发现新令牌后自己接上）放到以后，需要再设计「换了世界不能沿用旧记忆和旧意图」的检查。

### 3.4 局域网加作弊

保持拒绝，但把错误改成能看懂的：「局域网开了允许作弊，Bot 会被当成管理员，已拒绝接管；请关掉作弊重开局域网」。

## 4. 测试

**离线**

- Java：暂停时活动动作以 `GAME_PAUSED` 结束、已发出未确认的报 unknown、暂停期间 `act` 在写入前拒绝、读操作不受影响、不推进代次；`worldId: "auto"` 的命名和非法字符处理。
- 运行端：陪伴模式遇到 `GAME_PAUSED` 进入暂停、恢复后自动跟随、手动暂停不被自动恢复、有限任务失败不重试、暂停中不触发本能。

**实机（不动你的启动器实例）**

- 在模组的 Gradle 里加一个开发用客户端（`runClient`，游戏目录放在 `mods/mcbot-server-control/run/client`，已被 .gitignore 忽略，不会提交），把隔离测试服的世界复制一份进去，用 Quick Play 直接进单人世界。
- 开发客户端加一个只在 `-Dmcbot.validationFixture=true` 时生效的测试钩子：看到指定文件就打开或关闭暂停界面，脚本就能自动测「跟随中暂停 3 秒再恢复」「采集中暂停」「暂停中下命令被拒」。
- 运行时会在桌面弹出一个游戏窗口。

**用户验收（第 3 步）**：在你的启动器实例里装上模组、开单人世界，真人按 ESC、切窗口、退出再进。
