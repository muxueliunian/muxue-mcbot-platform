## 实验接口与结论限制

`mcbot-spike spawn/status/move/stop/remove` 是仅控制台或 OP 可用的实验入口。RCON 用于测试调度，不是生产控制链。首次生成的定位属于夹具初始化，不能计作移动成功。

角色使用世界实体 tick 驱动原版生存物理；虚拟连接不重复执行网络运动 tick。移动有有限 tick 与墙钟期限，但没有实现产品租约、Agent 断联控制和重生／跨维度策略。即使本轮移动通过，也不能将整个 G1 或 V1 标为完成。

真实测试脚本：`scripts/server-body-spike-smoke.mjs`。结果与未覆盖项在每次执行后更新，不用服务端自报状态替代独立协议或真人观察。

## 实测结果与失败记录

- 用户首次不能攻击的直接原因是测试服 `pvp=false`。保存退出后备份当前世界和配置到 `backups/serverbody-validation-pre-pvp-20261002-1532/`（世界 32 文件、6,288,571 字节，实际字节一致），只将隔离服改为 `pvp=true` 并重启。随后用户确认可以攻击。
- 两轮现场移动分别见 `output/serverbody-live-move.json` 与 `output/serverbody-live-move-repeat.json`。直线位移约 4.098 格，停止并等待惯性消退后坐标保持稳定。用户先未看到移动，要求重演；重演后明确反馈“非常正常”，因此保留整个反馈过程，不能只用首次服务端坐标替代真人观察。
- 墙体夹具位于 x=520，角色被阻在 x≈519.700；从高台落下后血量 20→14。24 个服务器 tick 的采样窗口内世界／生存 tick 都增加 24，重复计数为 0。
- G0 前三次脚本失败分别是名单末尾换行／未加载夹具、`execute if loaded` 成功文案假定含 count、重复设置 spectator 时空响应。均修正为实际响应或字段检查，保留 `serverbody-g0-first/second/third.json`；最终通过不是忽略断言。
- 受击脚本最初两次失败属于观察器：无 payload 的 bundle delimiter 导致读取 undefined，以及 `/tp` 整数 x/z 自动居中造成目标偏 0.5 格。已增加 payload 守卫并传显式小数坐标；没有将这些失败归因于产品。
- 真正受击失败见 `output/serverbody-hit-before-fix-2.json`：站位相距 2.5 格、不重叠、无墙、无主动移动，普通客户端空手攻击一次，血量 16.666668→15.666668，随后 10 次采样的水平位移均为 0。此断言能独立复现击退缺陷。
- 源码解释：`Player.attack` 将受击速度发给 ServerPlayer 客户端后恢复服务端旧速度；实验虚拟 listener 丢弃此包。已修复为消费自身运动包并在后续唯一物理 tick 前设置绝对速度，避免 send 内立即设置后又被原版覆盖，也不重复叠加。
- 修复后相同 hit 用例通过：扣血 1，最大水平位移约 1.989 格；自身速度包排队 1 次、消费 1 次、无待处理包；独立观察者看到位移，随后停止。G0／G1 同时回归通过。三组断言有重复，不累加成独立测试总数。
