## 已通过的真实程序场景

- 平地绕墙，保留墙体；一格上跳／下落、半砖楼梯、两格安全下落。均由原生输入完成，独立位置与生命字段核对，无导航受伤。
- 低顶与危险落点拒绝；持续跟随上台、走近高台箱子、拾取及采集后的高差拾取共用导航。唯一目标石头被移除，实际权威拾取回执确认新入包圆石1件。
- 空中停止后自然落地，后续无旧路线继续；跟随停止将回执时刻、原生惯性停稳、停稳后的不续跑分开检查。停止后首个新任务成功。
- 读取玩家、未激怒动物和明确敌对怪物；普通主背包钻石斧通过原生准备后防卫，以直接玩家伤害事件确认命中与伤害，再独立核对目标健康。
- 潜在群伤范围有中立动物时拒绝出手；自动防卫实际抢占原先持锁的等待。人工停止不因残留敌人重新授权；AI关闭自动防卫、排除指定UUID均有效。
- 普通AI的husk实际攻击身体后，观察到原生攻击自身证据；随后受控攻击途中停止，停止后的目标健康不再减少。
- 低血时尝试有界安全退让且不攻击；点燃苦力怕在可见但无安全退路的夹具中明确失败，没有穿墙或盲目出手。该苦力怕使用延长引信的测试夹具，**不证明正常短引信下必能逃生**。

最终无旧掉落干扰的完整证据：`output/server-navigation-defense-2026-10-03T12-31-32.716Z-33836/report.json`；入口为`scripts/server-navigation-defense-smoke.mjs --allow-fixture`。该脚本只作用于本批备份匹配的隔离服；`--navigation-only`、`--defense-only`和明确单场景诊断不算完整验收，不能用于授权后续模型试验。

最终JAR为233799字节，安装时直接比较实际字节。2ms是导航单片搜索的软时间目标；此次完整回执记录到约15.821ms的单片最大值，不能称硬实时上限。

## 实际聊天与连续运行

同一生产托管会话经测试玩家的真实游戏聊天运行**30分3.947秒**，完成153段原生走动／持续跟随，穿插台阶导航、原木采集、紧急进食抢占、防卫策略与抢占、材料查询和最终独立叫停。153次独立生命采样最低20；确认挖2／原生拾取2原木，自动进食6→11→16，有限自卫确认命中2次。叫停确认805ms，旧意图未续跑，宿主／玩家正常exit0。无图形客户端操作，不替代模型发Body请求。

原始证据：`output/navigation-defense-hosted-soak-2026-10-03T12-48-27.326Z-19420/`。**原始脚本的passed和formalThirtyMinuteEvidence不能作为全部19阶段均已有效核验的依据**：目标排除阶段读取生命的RCON选择器未限制单个实体，比较到两份相同错误文本。该阶段实际成功策略（autoDefend／armed／排除UUID）和没有防卫操作的观察有效，但生命不变的独立检查无效。原报告保留不改，旁存`validation-audit.json`注明缺口与后续证据。此前199.561秒短调试亦带此检查缺口，不计为全绿。

修正脚本从原生UUID四个整数直接转换身份，与Agent实际观察逐字段核对，然后按该UUID查询生命；必须解析为有限正数并确认为20→20，RCON错误文本不能通过。最终完整短复验`output/navigation-defense-hosted-soak-2026-10-03T13-19-01.652Z-7176/`有19阶段全部通过、204.085秒、叫停470ms，宿主／玩家／真实MCP均exit0。这两份记录分别证明连续运行和修正后的检查，不拼接成一次无缺口的30分钟全场景验收。

透明stdio观察器只镜像真实Agent请求的39工具名、成功策略回执和有限威胁身份，不创造工具调用。最终叫停必须先出现独立玩家聊天原因，再出现撤销确认，不能用Agent崩溃撤销冒充。普通跟随由程序执行，不逐段唤醒模型。此轮模型日志上下文约21k→57k，仅为本次样本，不构成与历史不同任务的性能对照。

本轮阶段首句游戏回复2.394–8.759秒；导航3.320秒首句／4.996秒终态，采集2.636秒首句／7.542秒终态，进食试验2.634秒首句，自动防卫2.616秒首句。进食试验终态包含RCON制造真实饥饿的时间，不能当作从饥饿触发到进食的反应延迟。宿主工具日志精度为秒，缺失的原生最后写入时间仍留null；不把首句、动作受理、终态和TPS混为一项。

## 实测与审查推动的修正

1. 搜索期间的正常停驻不再触发行走无进展计时；两者保留各自期限与预算。同一服务端tick去重，地形缓存仅在本tick内使用。
2. 跳跃按上升、跨越和落地分开核验，修复起跳首帧低于台面被误拒绝；真实路点到达容差与下一段扫掠配合，减少无意义重算。
3. 停驻挖掘后的高台拾取暴露了“接近顶点才给前进”的缺陷。诊断记录表明身体下降时仍在台阶侧面；改为经过净空与落点核验后，同tick原生跳跃和前进。没有改变速度或位置来伪造成功。
4. 武器选择优先实际可核验的原版武器，再考虑空手；按真实typed-NBT读取空附魔，排除未核验附魔／行为。只从0–35主背包取候选，不误用尚未交付的副手槽。
5. 危险通知比较语义变化，不因氧气补回、下落数值或距离微动反复唤醒模型；紧凑策略快照不再重复嵌套全量威胁。硬停止清公开防卫目标，旧收尾不能清新目标。
6. Codex宿主回归实际出现完成通知丢失，已用真实连接模块的确定性测试先复现再修复：同一读取批次到达的启动回执／完成通知先绑定确认的turn ID，再只结算一次；不相关旧轮不能提前释放新轮。
7. 防卫原生回调内同步重入停止的缺口由静态审查发现。现在保留原生调用scope，原生攻击／伤害入口再次校验；调用栈未退出时只撤授权并返回STOP_UNCONFIRMED，不能提前确认停写或接新操作。同期已发生Post继续只读保留可靠部分伤害，栈退出后拒绝迟到收据。这一重入路径有生产ControlSession／执行器的确定性离线证据，未将普通实服攻击测试冒充真实Mod回调故障注入。
8. 生存任务的终态审计与模型通知分开。自动日常进食、被硬停取消的有限防卫及被通知去重抑制的终态仍落入有限轮转JSONL；只记录历史，不改新任务状态，不标记成已向模型交付，也不触发额外唤醒。
9. 地面驾驶重新核验真实脚点到下一路点，避免无伤挤推后仍使用旧起点绕过火焰等危险。足底支撑用原生形状覆盖核验；下台阶时兼容原生onGround滞后一帧，但仅限已授权的drop段，保留原支撑锚点、空中范围、落点及新增的实际身体扫掠。修复过程中实际重现过正常下台阶误停，修正后重跑完整55项通过。无伤挤推的危险拐角有生产几何确定性测试，尚无真实生物挤推的专门成功证据。

测试夹具也有修正并保留失败报告：单读OnGround不能代替连续自然停稳；同材质平台导致采集目标不唯一；失败测试旧掉落可能满足后续拾取；怪物kill后尸体仍可挤推角色，须按literal UUID确认实际移除，`@e`会提前过滤死实体。只修正布置和核对，不放宽产品安全条件。

连续聊天首轮在5分钟策略阶段失败：测试措辞“会停止全部当前任务”触发既有宿主叫停匹配，先撤身体控制，Claude正常exit0。该记录不算异常进程崩溃，也不算30分钟通过；测试现在直接用产品判定函数预检非叫停消息。现有中文叫停仍属保守关键词匹配，描述性聊天也可能触发，需要后续单独改善交互语义。

短流程调试又发现固定2秒hunger没有到达预期饥饿状态：结束时实际food=20、saturation=9，程序未进食是正常行为。已改为观察原生food达到紧急阈值后立即清除夹具效果，而非按固定等待猜测。这两次失败分别保留在`output/navigation-defense-hosted-soak-2026-10-03T11-54-00.249Z-34276/`和`output/navigation-defense-hosted-soak-2026-10-03T12-02-31.289Z-37196/`。

最终导航版本的短流程已确认自动进食实际抢占跟随，两个权威收据为6→11→16。该次脚本仍要求food≥18而失败；满血时面包的5点营养超过4点缺口，既有策略选择不浪费是正确行为，验收应按此固定夹具检查food≥16。失败保留于`output/navigation-defense-hosted-soak-2026-10-03T12-36-49.776Z-23704/`，宿主与玩家均正常退出。上述失败不合并成一次通过，也没有为迁就夹具改变产品食物策略。
