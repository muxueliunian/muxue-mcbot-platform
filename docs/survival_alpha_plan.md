## 2. 寻路迁移方向

证据：旧 `mcp-server/src/movement.ts` 的 safeGoto；`action-policy.ts` 的安全移动规则；本地 `mineflayer-pathfinder` 的 AStar、Movements 与物理执行；新 `FlatRoute`／`FlatApproach`／`FollowCompanion`／`BodyPlayer`。

**选定方向：移植算法与策略，在游戏端实现一个统一导航 Module。** 目标、允许的移动策略、期限和取消是 Interface；三维搜索、地形评估、运动阶段与重算在内部。保持现有 move/follow/approach 等语义调用，不让 AI 一步步按方向键。旧路径仍保留，不把新身体重新绑定 Mineflayer。

可复用 A*、堆、目标距离判定和可续算思想；复用旧总期限、进度监视、到达后核验与不挖路/不搭桥策略。复制依赖源码时保留其 MIT 许可及来源。旧 Movements/physics 执行依赖 bot.registry、blockAt、实体/物品、physicsTick 和 Prismarine 物理模型，不能只换类型名直接运行。[上游项目](https://github.com/PrismarineJS/mineflayer-pathfinder)

游戏端继续用原生碰撞形状、完整身体扫掠、脚底支撑、实体阻挡和已加载地形。设计时的旧基线：FlatRoute 是二维同步 BFS，FlatApproach 固定脚底 y，BodyPlayer 只有前进输入。第二批已用统一三维搜索、原生跳跃与阶段核验替换生产导航，旧逐 tick 离地拒绝未原样沿用。需显式区分 walk/jump/drop/land，验证起跳净空、落点和落地，不能把任意离地当作获授权跳跃，也不能瞬移或改速度伪造到达。

搜索跨 tick 续算，独立限制每 tick 时间/展开量、总节点、读块、路径长度、重算次数和总期限。候选起点为每 tick 1–2ms或64次展开，**仅是待测初值**，不是性能承诺。世界读取仍在原生主线程，不能把 ServerLevel 丢到后台线程直接读。每次驾驶继续核验租约、代次、世界、路径安全和目标身份。

首批地形：半砖、楼梯、普通一格跳上、经验证不会受伤的有限下落（已交付上限2.5格，实测2格；早期3格候选未作为当前承诺）、绕障与动态目标。游泳、梯子、跨沟跑酷、自动开门、有伤下落、挖路搭桥不计这轮完成。卡住仅在既有授权范围内有限重算；预算耗尽说明原因并停止。

## 3. 工具资格、速度和背包

把“方块能被破坏”“工具能取得所需掉落”“用多久”分开返回。普通原版下，木镐能采石头；木镐破坏铁矿不等于获得铁矿掉落；黑曜石须满足钻石/下界合金等有效采掘条件。**这些用作验收案例，不写成按工具名字比较的固定等级表。** Mod可以修改工具组件、标签、速度和掉落资格。[NeoForge 1.21–1.21.1 工具说明](https://docs.neoforged.net/docs/1.21.1/items/tools/)

`NearbyResources` 当前已调用 requiresCorrectToolForDrops、ItemStack.isCorrectToolForDrops 和 getDestroySpeed，但只扫热栏，速度也只是基础值；不能把它说成已经实现完整AI策略。新评估需要返回候选物品引用、原生槽位、掉落资格 yes/no/unknown、预计挖掘时间及依据、耐久、不可用原因和推荐项。执行前对实际主手、目标和原生/NeoForge采掘条件再次核验，仍以实际完成与拾取回执报告结果。

默认 `fastest_valid`：先筛掉不满足掉落资格、目标掉落偏好、保护物品/耐久约束的候选，再比较预计速度。同速优先保持当前手持，减少搬槽。树木/沙子即使徒手能掉落，也可优先合适斧/铲。AI可选择保耐久、指定工具或调整保护清单；指定工具不合格时资源采集明确拒绝，不能为了服从“高速”损失目标掉落。精准采集/时运与目标物品存在冲突时应说明，而不是只选速度最大值。

候选评估不得通过临时换手、修改世界或触发实际挖掘来测速度。附魔、药水、环境和Mod钩子不能完整只读评估时标注估计范围/unknown；选定后再按实际装备状态核验。不能宣称 getDestroySpeed 的一个数值涵盖所有Mod或等于实际完成时间。

背包操作走原生菜单/库存动作，核验自身菜单身份、源/目标槽实际映射、组件、数量、carried 与回执；不得直接改ItemStack数量或把库存数组赋值当移动。只要求使用某物时暴露“准备/装备此物”的语义，让任务层内部完成搬到热栏；精确整理时才需显式移动槽位。吃完/防卫后恢复原工具同样核验槽位与物品，不能把旧快照写回。

R6作为依赖：无法完整序列化的无关物品可降级显示基本身份和“不可安全操作”标记，不能导致整个观察/聊天退出；写入仍须完整可信前置条件，缺失组件不得伪装为 `{}`。

## 4. 默认本能、统一仲裁与AI入口

**采用宿主程序的单一任务仲裁器，服务器提供快速权威感知和受控原生动作。** 本能运行在本地运行端，不经过模型回合；攻击冷却、物品使用tick、碰撞和最后执行门槛留在游戏端。所有本能、普通任务、AI显式动作共用同一Body写互斥，不再另起直接操作身体的定时器。快速状态读取与全量库存/组件读取分开，不能为每个感知tick给模型塞完整NBT。

旧 reflexes.ts 的食物缺口/紧急阈值/间隙进食、危险通知等经验可以复用；foodsByName静态表、名字排除表、固定650ms攻击和直接controlState调用不能直接当新版Mod规则。当前RuntimeMonitor约500ms观察，且模式切换时会暂缓读取；在同一运行端调度中增加独立于模型和陪伴稳定状态的紧凑感知分支，不能因companion正在切换而跳过危险感知，也不能因此跳过硬停止或租约保护。采样周期与成本需实测，不承诺零延迟或把陈旧快照叫实时。

首版服务端提供原生威胁证据和动作执行，不自行启动另一套抢占写入或偷偷推进controlGeneration。现有ServerBody会把未经自身流程解释的代次变化当成失控；若实测证明宿主感知／取消／停止往返不满足防卫要求，再单独设计可鉴权、带原因与所有权交接回执的服务端抢占协议，不能靠重读并静默接受新代次修补。首版需单测并实服记录威胁出现→感知→停止旧动作→首个防卫动作的分段延迟；普通RPC等待不得阻塞感知与硬停止通道。

默认行为建议：

- **自动进食开启**：使用当前栈/玩家的原生食物属性，普通情况兼顾缺口和饱和度；饥饿/恢复生命紧急时允许不追求零浪费。默认保护珍贵食物，排除已知负面或未核验副作用；未知Mod食物交给策略/Adapter，不能按名字猜。完成须核验原生消费结果，处理中断、容器返还物和unknown。
- **自动防卫开启**：对进入防御范围的明确敌对威胁、或正在攻击自身的生物做近距防卫。中立生物不因靠近而被主动激怒，玩家/友军默认排除。身份、维度、距离、视线、冷却及群伤风险执行前重查；未知Mod武器的范围伤害不擅自用于自动防卫。点燃苦力怕、低血等优先尝试已确认安全的有限退让，无路则告警，不盲冲。无无限追敌、无危险追击。
- **快速正确工具开启**：采用上一节的fastest_valid规则；AI可调整保耐久、禁用物品和明确工具选择。

仲裁顺序是约束，而非两条同时写的循环：硬停止/失租约最高；迫近危险、自卫和紧急进食优先于普通工作，日常进食尽量放在任务安全间隙。进食可作为持有外层token的受限子步骤，结束后重查再继续同一授权任务；紧急防卫若须抢占，先取消并确认旧原生动作停止，再取得写权，保留原任务已完成数量。无法确认停写时不强行抢锁或开第二条写入通道，报告阻断；旧finally/晚到回执仍不能释放新任务锁。首版防卫后不隐式重放旧挖放/建造任务，由AI根据结果明确决定新的剩余任务。人工硬停止清掉全部执行意图，本能也不能自动接管或复活旧任务；区分保存的策略与当前armed授权，只有新的明确授权在有效控制权内才能重新armed。主动关闭某本能后同样终止其在途行为。

实现时需把下面条件写入同一仲裁契约：

- 抢占前先阻断新普通写入，并撤销容器、采集、陪伴及其子任务和直接原子动作的旧意图，不能只cancel某一个任务类。停止确认后，同一同步交接退役旧所有者并取得新token；每次await后重查仲裁epoch、租约和策略版本。
- 紧凑感知在companion切换早退之前执行；仲裁器分阶段推进，不能await整段战斗/进食而停止采样。硬停止有独立优先通道，并区分人工停与程序抢占的原因；stop失败或动作unknown保持阻断，不在下次采样自动重试。
- 日常进食间隙由外层任务显式授予：暂停发步骤，确认没有在途原生写入和不明carried状态，再借token给有限子步骤。结束后核验手持及任务上下文；若期间推进控制代次或任务被取消，不继续旧任务。
- 感知超时/过期不等于无威胁；点燃苦力怕等紧急场景须记录反应失败，不能宣称宿主方案必能及时救险。

语义 Interface（第一批已注册生存／工具／进食，第二批已接威胁、防卫与危险事实；下表保留完整设计目标，具体字段及已验证边界以最新协议和验收为准）：

| 入口 | AI能读/做什么 |
| --- | --- |
| `get-survival-state` | 生命/最大生命、饥饿/饱和、氧气/火焰等危险、当前手持、威胁摘要、正在执行的本能、被中断任务与策略版本 |
| `assess-tool` | 对明确方块与采集目标评估可采资格、预计速度、耐久/掉落偏好和推荐物品；执行时仍重查 |
| `set-reflexes` / 读取有效策略 | 开关进食/防卫，修改受限阈值、目标排除、追击范围、工具偏好；返回实际生效值、修订号与拒绝原因 |
| 装备/物品使用/明确防卫任务 | AI能发出受限高层决定；内部复用同一选择、仲裁、原生执行和结果逻辑，不能另复制一套自动行为 |

感知需携服务端tick/时间、观察修订、策略修订和实体UUID，说明缺失/过期信息；策略写入带预期修订避免旧AI决策覆盖新用户设置。行动仍看最新原生状态。威胁包含敌对判断来源、是否锁定自身、距离/视线、是否处于攻击/爆炸准备和未知分类；“不知道”不能编成安全。

事件只在危险出现/改变、本能开始/结束/失败、任务被抢占、无食物/无可用工具等必要变化时唤醒AI；普通tick、每次挥击和重复吃同类食物不反复唤醒。AI始终可以主动读取最新快照，并在下一受控边界改变策略。示例：默认击退靠近的僵尸 → 事件说明打断了采集及当前血量 → AI读状态决定继续采剩余材料或转移；AI说“别主动打这只生物”后，策略排除须立即生效并停止相关在途追击。

## 5. 原建筑 skill 的实际状态

原正式技能在旧工作目录 `.claude/skills/minecraft-building/SKILL.md`，仍存在；`docs/research/minecraft-building-skill-draft` 是较旧草稿，不能替代正式版。旧正式版含edit-blueprint/import-schematic，部分草稿说明已过期。新整理仓库保留了legacy建筑源码，但未分发私人技能、评分与蓝图资料。

- **可迁移**：选址→设计→画图检查→材料预检→预览→施工→实物复查流程；蓝图相对坐标、旋转、形状展开、局部编辑、图纸解码和静态渲染的纯逻辑。渲染资源须独立检查来源/许可，私人人设、偏好和评分另选迁移，不自动拷贝。
- **仍属旧身体**：build、prepare-materials、find-site、survey-site、preview、飞行/脚手架及世界复查执行器依赖Mineflayer/旧TaskHandle，部分虚影用RCON。新ServerBody目前39工具仍没有这套建筑执行入口。
- **新身体缺口**：受限区域观察、材料与热栏调度、有限BuildTasks、目标朝向/上下半等状态放置及核验、预览归属与清理、施工后的世界差异检查。当前place-block只确认方块类型/扣料，拒绝门/床/双格植物，不能直接保证旧蓝图效果。

迁移时沿现有Body／任务锁／回执，替换旧执行器；旧技能的失败重试/同参数恢复规则必须重审。新计划只在显式新任务、重新观察后计算剩余方块；unknown与人工停止不自动重放。先用17个完整方块的3×3小亭（四角柱各高2＋9块屋顶）验证预检、缺料/冲突、逐格原生结果、聊天、停止和部分完成，再扩大样式与属性。

R3游戏模式移除了通用文件工具并禁用slash技能，因此只把旧skill文件放进新目录也不会自动生效。由宿主按白名单只读加载选定技能和固定参考内容，或提供受控内容资源入口；不恢复Read/Write/Bash来绕开它。技能自动记录评分应走限定范围接口，不能借游戏聊天获得任意文件写权。**设计资产没有丢失，新执行接线尚待迁移。**

## 6. 两轮推进与硬验收

1. **第一轮：物品/工具/进食与感知基座。** 背包到热栏、工具资格及默认快速策略、受控食物使用、AI状态与策略入口、统一仲裁骨架；R6必要降级同步处理。并行验证小范围三维导航原型，先发现离地/落点问题，不把原型标为完成。
2. **第二轮：导航整合、自卫与试玩交付。** 用统一导航替换各调用点；近距自动防卫/安全退让接同一仲裁器；串联跟随、采集、进食、战斗抢占与AI策略修改，完成真实Agent和30–60分钟真实生存混合验收，提供启动包/配置检查/限制说明。

两轮是功能批次目标，不承诺两次短会话内恢复旧版所有寻路、战斗或建筑能力。上述自卫与AI决策入口是用户最低要求，未通过时不得称Alpha达标；复杂战斗、合成熔炼、完整建筑和通用Mod覆盖不暗中塞入验收。

必须包含的案例：

- 食物/工具在热栏外、目标槽被占、物品/组件改变、无可用工具、即将损坏；每次真实消费与移动数量守恒，未知不重试。
- 原版木镐采石头/不得把铁矿当可获掉落，铁镐不得把黑曜石当可获掉落，钻石等合适镐可获；木头/沙子比较不同合格工具速度。设计时矿石/沙子不在资源目录；2026-10-04仅新增煤/铁/铜及深层目录代码，沙子与黑曜石仍未纳入有限采集，矿石实服待验。只读评估不等于允许破坏任意方块。
- 木/石/铁/金/钻石及附魔、精准采集/时运、状态效果和代表性Mod工具，确认资格、速度估计和实际结果分开；不满足资格不挖、没有完整评估则明确unknown。
- 僵尸靠近、实际受击、中立生物未激怒、玩家/友军、苦力怕点燃、退路危险、目标离开/替换；默认防卫、AI关闭或改变目标策略均有效。
- 挖掘/跟随/容器进行中进食或防卫；同时收到人工停、租约过期、晚到旧回执，不得并发写入或复活旧任务。停止后的首个新任务仍首次成功。
- 慢HTTP、模式正在切换时仍能感知威胁；抢占中硬停/关闭策略、stop失败、两次抢占回执乱序、进食子步骤取消，均不能凭迟到结果开新动作或续跑旧任务。
- 半砖、楼梯、一格上跳、安全下落、低顶、动态障碍、缺支撑、未加载区块、空中叫停；按真实位置/速度/伤害/世界字段判定，不用瞬移模拟证明通过。
- 正常生存环境里的真实Agent连续任务，分别记首次游戏回应、动作受理、完成、停止确认与最后实际写入；缺数据保持未测，不用模型TPS解释链路问题。

制定本设计时未开服或使用模型；后续第一批开发的实服与Claude-b结果已另记验收。旧仓库与私人技能未改。后续继续中文与pwsh；保留未提交修改；非必要禁止计算/校验任何哈希或指纹，普通比较直接核对字节或字段。新一轮真实账号测试仍按当天用户选择与隔离服备份规则执行。
